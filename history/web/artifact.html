설계 결정

왜 이렇게 만들었나

  • 레이어 우선순위 zIndex 1010 — 기존 WFS·WMS 레이어(1000) 위에 표시해 시설물이 가려지지 않게 함
  • declutter: false — 목록 건수와 지도 표출 건수를 일치시키기 위해 라벨 겹침 제거 기능을 끔
  • AbortController + 요청 순번 — 행정구역을 빠르게 바꿀 때 이전 응답이 나중에 도착해 화면을 덮어쓰는 문제 차단. 취소로 생긴 AbortError는 오류 UI를 띄우지 않음
  • 이벤트 ID 분리 — 클릭 facility-click-layer, 호버 facility-pointer-move로 기존 wfs-general-click과 분리하고, 피처를 벗어나면 커서를 즉시 복원
  • 공간 쿼리 — LEFT JOIN LATERAL + ST_Intersects(LIMIT 1)로 g_emd의 GIST 인덱스를 태우고, 행정구역은 emd_cd LIKE code || '%' 접두어 한 조건으로 필터
  • extent 변환 최소화 — 폴리곤 전체가 아니라 ST_Transform(ST_Envelope(geom), 3857)로 BBOX만 변환
  • 대량 렌더링 — 2,474건을 DocumentFragment로 한 번에 삽입, XSS 방지를 위해 textContent 사용

왜 SVG로 그렸나

  • 이미지 파일을 추가하지 않음 — buildFacilityIconUrl()이 SVG data URI를 만들어 씁니다. 확대해도 선명하고, 색만 바꿔 재사용할 수 있으며, 저장소에 바이너리가 늘지 않습니다
  • 스타일 캐시 — 종류·색·선택 상태 조합을 facilityStyleCache에 담아, 피처 2,474건을 그릴 때 ol.style.Style을 반복 생성하지 않습니다
  • 색은 글리프에 적지 않음 — 글리프 안의 문자열 COLOR를 핀 색으로 치환하므로, 새 종류를 추가할 때 색 처리를 신경 쓰지 않아도 됩니다
  • 확장 방법 — FACILITY_ICON_TYPES에 { type, keywords, glyph } 한 줄을 추가하면 새 종류가 잡힙니다

팝업 헤더가 화면 위로 잘리던 문제

팝업은 시설물 위쪽으로 그려지는데, 화면 위쪽 시설물을 선택하면 헤더(아이콘·제목·배지)가 잘려 보이지 않았습니다. 검증 중에 발견했습니다.

  • 오버레이에 autoPan(여백 20px, 250ms)을 켬
  • 그것만으로는 부족 — 처음 위치를 잡는 시점에는 "불러오는 중" 상태라 팝업 높이가 작아, autoPan이 실제 높이를 모른 채 계산함
  • 상세 내용을 그린 뒤 setPosition(coordinate)을 한 번 더 호출해 확정된 높이로 다시 계산하도록 함

이번에 겪은 함정 2가지

  • 동시 push 시 매니페스트 커밋 충돌 — 매니페스트 단계가 clone → sed → push 구조라, 여러 저장소를 한꺼번에 push하면 한 잡이 cannot lock ref로 실패합니다. 실제로 mapservice-rest 잡이 실패해 이미지는 올라갔는데 태그 커밋만 빠진 상태가 됐고, 잡 재실행으로 복구했습니다
  • 롤아웃 중 503 — 옛 파드 종료와 새 파드의 Eureka 등록 사이에 게이트웨이가 잠시 503을 반환합니다. 배포 직후 503은 몇 초 뒤 다시 확인하면 됩니다
